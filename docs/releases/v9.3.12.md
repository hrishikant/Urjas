# Ūrjas v9.3.12

**Preview for physical-strap evaluation.** The stable v9.3.11 release and AltStore source are unchanged.

## Preview 2 UI corrections (build 225)

- The detected-workout card now opens the existing searchable sport selector, including Badminton
  and the full workout catalogue. Choosing a sport and confirming saves the manual label; cancelling
  leaves the detected workout pending.
- Header text and Today controls follow the light/dark canvas when the day-cycle sky is switched off.
  Enabled sky backgrounds retain their on-dark text.
- Metric readings and shared summaries no longer append a second unit to already formatted values.
  Display conversions such as pounds and Fahrenheit retain their selected unit.
- Coach provider selection uses a menu so full provider names remain readable on an iPhone.

Selective integration from NOOP v11.7.0, not a wholesale upgrade of the fork.
Only the sync/rescore, sleep, WHOOP connection/measurement and recovery work is included.
Coach, extra Today cards, training-load charts and expanded Apple Health imports are not part of this update.

## Sync and score preservation

- The automatic rescore gate tracks scoring inputs across devices instead of only the original device's
  heart-rate count. Duplicate offloads can skip unnecessary full-window analysis. Edits and recalibration
  still force analysis, and a new calendar day or wider requested window invalidates the previous result.
- Analysis takes its in-flight lock before its first asynchronous store read, preventing overlapping passes.
- Failed primary sensor reads abort before replacing computed results. Failed score/activity writes surface
  an error and do not advance the completed-analysis watermark, allowing the next trigger to retry.
- When a detected night has no sleep R-R input, a previously measured HRV/recovery snapshot from the same
  day and recorded provider can be retained. This does not invent a new measurement, fill across days or
  providers, override available R-R analysis, or undo a sleep edit. The retained result has no newly
  calculated recovery-driver explanation.
- Derived workout replacement is transactional. An insert failure rolls back the replacement rather than
  leaving the detected-workout list empty. A detected row cannot overwrite a manual/imported workout
  with the same database key.

## Sleep

- A no-motion night with no source-provided sleep session can use the upstream HR-only fallback. Real
  R-R intervals remain necessary for HRV. HR-only stage estimates carry an additional marker in the
  existing stage JSON; no new database column is introduced.
- The fork retains its off-wrist, maximum-duration and daytime-nap guards. Unlike the upstream fallback,
  a flat partial HR download without sleep/wake contrast is declined rather than labelled as sleep.
- Fragmented nights can bridge short motion-labelled interruptions only when heart rate corroborates
  sleep. Dense nights that already contain a viable sleep run retain their existing detection path.

## WHOOP connection and R-R units

- After three unacknowledged WHOOP 5/MG handshakes end in disconnects, automatic reconnects can leave
  that handshake suppressed and keep standard-profile live HR running. A user-initiated Connect retries
  full pairing; a genuine bond or forgetting the device clears the per-device suppression.
- Explicit authentication-refusal handling and WHOOP 4 handshake/offload sequencing are unchanged.
  The live-HR fallback does not claim an encrypted bond or unlock historical commands.
- WHOOP 5/MG standard-profile R-R values use their raw millisecond units. WHOOP 4 and other families
  retain the Bluetooth-standard 1/1024-second conversion. Existing stored intervals are left untouched.

## Recovery accuracy

The second scoring pass now attaches the nightly skin-temperature deviation before calculating recovery,
its drivers and its diagnostic trace. Missing temperature data or an unusable baseline remains absent;
temperature cannot bypass HRV calibration.

## Compatibility

The custom live workout start/stop, post-sync workout detector and confirmation card, sport ranking,
raw-IMU refinement, manual labels, Live Activity and Today customizations are retained.
No database migration, raw-IMU table removal, bundle-ID change or signing change is included.
Existing R-R history is not guessed or rescaled retroactively.

This update does not remove iOS background-execution limits or guarantee continuous real-time sync.
Sleep and sport detection remain estimates; newly available evidence can legitimately change their results.

This selective integration targets the owner's native iPhone app and the shared macOS implementation.
Android behavior is deliberately unchanged in this iteration (only the shared version label is aligned);
the features above must not be advertised as an Android upgrade. Database and backup schemas remain
unchanged across platforms.

Connection behavior still requires a trial on the owner's physical strap; simulator builds cannot establish
radio/firmware compatibility.
